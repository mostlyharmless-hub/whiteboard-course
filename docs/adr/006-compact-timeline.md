# ADR 006：配音时长驱动的紧凑时间轴

- 日期：2026-09-15
- 状态：已采纳（视频课默认用此模式）
- 影响：`pnpm tts --timeline compact`、`pnpm timeline --transcript`（`remapToTranscript`）；CLAUDE.md 第 2 节

## 背景

ADR 004 让配音沿用原录播时间轴。TTS 语速比原讲者快，每段说完后到下一段开始之间空出十几秒，加上原视频的操作停顿，7 分钟里约 2 分钟静音，用户反馈"两段话中间停顿太长"。

## 决定

1. `pnpm tts --timeline compact`：每段紧接上一段结束 + 固定间隔（默认 700 ms），开头留 2 秒；总长 = 语音总长（样例 306.7 秒，原 420.5 秒）。写出的讲解稿时间是新时间轴、文本已纠错。
2. `pnpm timeline --in <脚本> --transcript <新讲解稿> --out <新脚本>`：板书脚本**不重新生成**，每条动作按锚点段落内的相对位置把 `at / until` 映射到新窗口，`reveal_ms` 不超过新窗口剩余；段落文本与时间、小节起止、`duration_ms` 全换成新讲解稿的；最后套用 ADR 005（翻页只能提前进 700 ms 的间隔）。
3. 原时间轴模式（`--timeline original`）保留，用于需要和原视频对齐的场景。

## 影响

- 视频课时长由内容决定（样例 5:07），不再等于原课程时长。
- 段内相对位置映射意味着板书节奏按配音等比压缩，"老师先落笔再开口"的关系保持不变。
- 首页标题卡在 0 s 开始书写，语音 2 s 开始。
